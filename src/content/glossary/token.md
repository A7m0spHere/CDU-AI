在文本进入[大语言模型](/glossary/llm/)计算之前，输入内容会先经由**分词器**（Tokenizer）拆分为离散的编号片段，每个片段即为一个 token。模型后续的注意力计算、输出生成以及接口用量统计，均以 token 序列而非原始字符数为基础。

## 切分粒度与词表差异

Token 并不固定对应单个汉字或单个英文单词，其实际粒度由模型采用的词表（Vocabulary）与子词切分算法（如 BPE）共同决定：

- **英文与代码**：高频短词或常见关键字通常对应 1 个 token，长词或生僻词会被拆分为词根、词缀或标点片段。
- **中文文本**：常见字或高频双字词通常占 1 至 2 个 token，生僻字、特殊符号及连续空白符可能被进一步拆分为多个字节级 token。
- **跨模型差异**：不同模型在训练分词器时使用的语料分布与词表规模不同，同一段文本在不同模型下切出的 token 数量往往存在差异。

## 计量范围与构成

单次模型请求消耗的 token 并非仅包含用户当前输入的提示词，而是涵盖完整进入本轮上下文的全部内容：

| 构成项 | 包含内容 | 计量归属 |
| --- | --- | --- |
| **系统与历史上下文** | 系统提示词、前置规则与多轮对话保留的历史消息 | 计入输入（Input） |
| **当前输入与附件** | 本轮提问文本及随请求送入的文档、代码片段 | 计入输入（Input） |
| **模型生成内容** | 返回给用户的全部文本与结构化内容 | 计入输出（Output） |
| **推理与工具回传** | 启用推理过程或工具调用时进入上下文的中间结果 | 视产品实现计入相应额度 |

## 上下文窗口与计费

Token 将模型的容量限制与资源消耗统一起来：

- **上下文窗口**：[上下文窗口](/glossary/context-window/)定义单次请求能够容纳的 token 总上限（输入与输出之和）。当累计长度接近或达到上限时，系统会触发截断、压缩或拒绝请求。
- **按量计费与额度**：在[按量计费](/glossary/usage-based-billing/)的接口中，费用通常按每千或每百万 token 分别核算输入与输出单价；输出 token 单价通常高于输入。网页端对话产品虽常隐藏具体数值，但长对话触发的轮次或用量限制同样受底层 token 消耗制约。

## 概念边界

- **不等于字数或字符数**：中文不存在统一的「1 字 = N token」换算比例，实际消耗需以对应模型的官方计数工具或接口返回为准。
- **不代表输出质量**：token 数量仅反映文本长度与计算开销，与回答的准确度、推理深度没有直接因果关系。
