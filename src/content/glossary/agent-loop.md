## 一句话说清

Agent 干活的基本节奏：调模型 → 执行动作 → 检查结果 → 决定继续还是停。这个圈一直转到完成，或者触发停手条件。

## 打个比方

写作业、检查、改错、再检查，直到全对，或者到了交卷时间。

## 它是怎么运作的

1. 计划：这一步要做什么。
2. 执行：调用工具，真的做。
3. 检查：跑测试、比对结果、看是否有报错。
4. 决策：继续、修正、暂停等人确认，还是收工。

## 你会碰到它的场景

- 改代码，直到测试全部通过。
- 批量修文档格式，逐篇检查。
- 反复调一个脚本，直到输出符合预期。

## 常见误解

- 以为它会自己停下来。必须有停手条件：轮数上限、预算上限、成功标准。
- 以为循环越多越好。没有检查的循环，只是把同一个错误重复更多次。
- 以为失败了它会自己发现。检查手段是前提，没有检查就没有「失败」这个概念。

## 想再深入一点

可靠的循环通常有两条规则：连续同类失败就停，高风险动作先确认。缺了这两条，Agent 会越转越贵。
