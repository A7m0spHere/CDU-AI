## 一句话说清

主 Agent 把一个大任务拆开，派给几个「分身」各自去做。每个分身有自己的上下文，做完只把结论交回来。

## 打个比方

项目经理把「查资料」和「做图」分别派给两个人。他们各自忙各自的，最后交两页摘要，不需要把全过程倒给项目经理。

## 它是怎么运作的

1. 主 Agent 判断任务能不能拆成互不依赖的几块。
2. 分别派发，每个子任务独立进行。
3. 子 Agent 只回传结论，不把全部过程塞回主线。

## 你会碰到它的场景

- 同时检查十个页面的文案是否一致。
- 一个查资料、一个写初稿、一个做事实核对。
- 资料量太大，主线上下文装不下，拆开分别读。

## 常见误解

- 以为子 Agent 共享记忆。通常各有各的上下文，只交换摘要。
- 以为派得越多越好。每个子任务都要花时间和费用。
- 以为可以无限嵌套。层级越深，越难控制，也越容易跑偏。

## 想再深入一点

它适合「独立、可验证」的子任务。强耦合的任务硬拆开，反而会丢信息、互相矛盾。
