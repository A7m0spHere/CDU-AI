## 一句话说清

让模型按「想一想 → 做一步 → 看结果 → 再想」的方式推进，而不是猜完就一次写到底。

## 打个比方

修水管：先看哪儿在漏（观察），拧一下（行动），看还漏不漏（观察），再决定下一步。没人会闭着眼睛拧十下。

## 它是怎么运作的

1. 推理：根据现有信息判断问题在哪。
2. 行动：挑一个动作，比如搜索、读文件。
3. 观察：读取真实返回。
4. 带着新信息回到第一步，直到可以收尾。

## 你会碰到它的场景

- 排查报错：先看日志，再改一处，再跑一次。
- 查资料写报告：查到什么再决定下一步查什么。
- 做数据核对：抽一条对一条。

## 常见误解

- 以为它会自己一直想下去。不设停手条件，它可能绕圈。
- 以为观察结果一定可靠。工具返回错了，它就会沿着错误往前走。
- 以为这是某个产品的专有功能。它只是一种通用的组织方式。

## 想再深入一点

ReAct 的价值在于让模型每一步都接触真实反馈。没有反馈的「思考」，很容易变成自说自话。
