在这篇教程中，你不需要掌握编程，也不需要提前理解复杂的技术原理。我们会选择一个 Agent 工具，完成安装，然后让它亲自在你的电脑上制作一个介绍成都大学的网页。

## 01. 先选择一个 Agent

现在已经有不少可以实际执行任务的 Agent 工具。它们的使用方式、擅长领域和学习成本各不相同。

第一次使用，我们主要介绍两个国产Agent。

### WorkBuddy：适用于小白

如果你从来没有接触过这种Agent，建议优先尝试 WorkBuddy。

它偏向于日常办公和文件处理。

它的优势是使用场景容易理解，开箱即用，还可以白嫖；

缺点就是客户端有点臃肿，harness架构很一般，不适合作为开发项目使用。

### ZCode：目前国产最好的Agent

如果你对使用 AI 创建网页、编写程序或者开发小工具感兴趣，可以尝试 ZCode。

它更侧重项目文件和开发任务，提供工作区管理、工具调用、文件修改与结果审查等能力。

即使你完全不会写代码，也可以通过自然语言提出开发需求。不过，与 WorkBuddy 相比，你可能需要逐渐理解更多有关文件、项目和运行环境的知识。还有，需要付费，但是它可以设置第三方供应商。你不一定必须购买他们的套餐（智谱的套餐性价比很低）

### 还有其他选择吗？

当然有，但这些就因人选择。

当然，我会提及一个开源项目 DeepSeek Harness（DSH），它采用插件化架构，能够通过扩展机制增加 Agent 的能力。

不过，DSH 目前仍处于开发者预览阶段，可能存在兼容性变化，所以我不推荐新手，小白使用DSH。

本教程不会要求你安装所有工具，**选择其中一个就行了。**

## 03. 为 Agent 准备一个开发文件夹

在开始之前，先给 Agent 一个明确的工作范围。

（这是一种推荐的开发方式，具体原因，我在后文再解释）

在电脑桌面或其他方便找到的位置，新建一个文件夹，命名为：

`CDU-介绍网站`

这个文件夹就是我们接下来的练习区域。

请在工具中选择它作为本次任务的工作目录，或按照软件提供的方式授权访问该文件夹。

<!-- first-agent:choices -->
<!-- first-agent:tool workbuddy -->

WorkBuddy 可以在新建任务时选择工作目录。

<!-- first-agent:media M03-W -->
<!-- first-agent:tool zcode -->

ZCode 则可以打开这个目录作为项目工作区。

<!-- first-agent:media M03-Z -->
<!-- first-agent:endchoices -->

为什么要单独创建一个文件夹？

因为 Agent 会进行实际读取、创建或者修改文件。使用一个独立的工作区，方便管理，也能减少开发中的风险。

## 04. 第一次任务：让 Agent 制作一个网页

现在，我们正式开始第一次实践。

任务是：**制作一个介绍成都大学的网页。**

找到 Agent 的对话输入框，复制下面的任务要求并发送。

<!-- first-agent:copy task -->

> 请帮我制作一个介绍成都大学的网页。
>
> 具体要求：
>
> 1. 网页包含成都大学的介绍、校园生活等内容，整体美观、简洁，适合大学生阅读。
> 2. 相关布局，主题可以先询问我具体设计，再开发。
> 3. 请生成一个名为 `CDU.html` 的文件，保存在当前工作区中。
> 4. 网页应该可以直接通过浏览器打开，不需要安装额外软件或运行服务器。
> 5. 涉及学校的具体信息，请尽量依据[成都大学官方网站](https://www.cdu.edu.cn/)核实；无法核实的内容不要编造。
> 6. 仅在当前工作区内工作，不要修改其他文件。
>
> 完成后，请告诉我如何打开这个网页。

发送后，你可能会看到 Agent 分析需求、创建文件和编写网页代码。

如果出现文件写入或命令执行权限请求，请先查看具体操作内容，再决定是否批准。也可以开启自主模式（zcode）减少授权的操作。

## 05. 打开你的第一个网页

Agent 告诉你任务完成后，先别急着结束。

现在找到刚才创建的 `CDU-介绍网站` 文件夹。

如果任务执行成功，你应该能看到：

`CDU.html`

这是一个 HTML 文件。HTML 是网页使用的一种基础标记语言。

**双击打开这个文件。**

正常情况下，它会使用系统默认浏览器打开，展示 Agent 为你制作的成都大学介绍页面。

<!-- first-agent:media M05 -->
<!-- first-agent:media M06 -->

如果双击后没有使用浏览器打开，可以右键点击文件，选择「打开方式」，再选择 Chrome、Edge 或其他浏览器。

现在观察一下你的网页吧！

但我们还可以继续尝试一件事。

## 06. 不喜欢这个设计？让 Agent 再修改一次

刚才的网页，是 Agent 根据你的要求设计的。

如果你不喜欢，可以描述这些需求进行更改。

现在，重新回到 Agent 的对话界面，告诉它哪里需要改进。

例如：

<!-- first-agent:revisions -->
<!-- first-agent:revision visual -->

**调整视觉风格**

> 我希望这个网页更有现代感。请优化配色、排版和视觉层次，但保留已有内容。

<!-- first-agent:revision content -->

**优化页面内容**

> 我希望增加一个介绍校园学习与生活的板块，设计成卡片布局。请不要编造学校的具体信息。

<!-- first-agent:revision mobile -->

**改进手机体验**

> 请优化这个网页在手机屏幕上的显示效果，让文字、图片和卡片布局能够适应较小的屏幕。

<!-- first-agent:endrevisions -->

当然，你也可以根据自己的喜好提出修改意见。

Agent 完成修改后，重新打开网页，或者在浏览器中刷新页面，看看发生了什么变化。

<!-- first-agent:comparison -->

你会发现，我们并不需要重新制作整个网页，而是可以让 Agent 在已有成果上继续工作。

这正是 Agent 很实用的一点：**它不仅可以执行一次任务，还可以根据后续要求不断修改和完善成果。**

## 07. 简单总结

回顾一下这次操作：

你提出需求，让 Agent 制作一个网页。

Agent 尝试理解你的意图，通过工具创建和编辑文件，最终生成了一个可以用浏览器打开的页面。

随后，你还可以根据自己的判断要求它继续修改。

不过，这并不代表 Agent 生成的结果一定正确。或许给你做出来的东西还存在一些BUG，或者信息编造。

因此，我们仍然需要亲自打开、检查和判断最终成果。

**Agent 可以替你执行任务，但你仍然负责明确目标、判断结果是否符合预期。**

这只是一个开始。

接下来，我们会继续学习如何描述任务、管理 Agent 的操作权限，以及利用它完成更复杂的实际工作。
