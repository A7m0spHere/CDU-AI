在上一篇[第一次使用 Agent](/guide/first-agent/) 中，你已经照着示例让 Agent 做了一个介绍成都大学的网页。

你可能注意到了，当时发给它的并不是一句“帮我做个介绍成大的网页”，而是带编号的几条具体要求：写什么内容、先询问设计、生成哪个文件、怎么打开、不要编造学校信息、不要修改工作区之外的文件。

这一篇就讲清楚**给 Agent 写提示词的基本思路**：当 AI 不只是聊天、而是真的要动手操作文件或执行步骤时，任务到底该怎么描述。

## 为什么不能只给 Agent 一句“许愿式”指令

假设快期末了，你的电脑里有一个临时文件夹，里面混放着十几份课程 PDF、实验截图、Word 笔记，还有几个名字叫 `最终版`、`最终修改版2` 的文档。

如果你直接打开 Agent，只发一句：

> 帮我把这个文件夹整理一下，顺便把重点汇总成一份复习文档。

你心里想的是“别删我原文件，按课程建几个子文件夹分类，再顺手列个提纲”；但在 Agent 看来，这句话留下了太多需要自己猜的空白：

- **直接移动还是复制？** 它可能会把原本的目录结构全部打乱，甚至直接重命名原文件；
- **哪些算“垃圾文件”？** 它可能把你留着备用的旧截图或草稿当成冗余文件处理掉；
- **汇总文档写多细？** 它可能漏掉重要章节，或者为了把提纲凑完整，自行补写讲义里没有的内容。

和普通聊天 AI 对话时，问得笼统，顶多得到一段泛泛的文字建议，换个问法重问就行；但交给 Agent 时，它会**带着这些未经确认的猜测直接操作文件**，一旦跑偏，返工和排查的成本会高很多。

## 好用的任务描述，通常说清这四件事

给 Agent 交代任务，不需要背诵复杂的长模板。动手前对照下面四个问题，把关键信息补全，就能避开大多数跑偏。

### 1. 目标与输入：你要做什么，材料在哪里

先说清楚**最终要交付什么成果**，以及它应该**根据哪些材料**去做。

- 说清产物形式：是一份 Markdown 复习提纲、一个可直接双击打开的 `index.html`，还是重新分类后的文件夹；
- 指明信息来源：优先读取当前工作区里的哪些文件，需要联网核对时以哪个官方页面为准，不要让它自己漫无目的地翻找或凭印象编造。

### 2. 边界与禁区：能动哪里，不能动什么

提前划好“工作范围”和“不能碰的红线”，比事后挽救省心得多。

这也是上一篇专门让你新建独立文件夹 `CDU-介绍网站` 的原因之一——先从目录层面把影响范围圈小。同时，在任务描述里也可以明确写出限制条件，例如：

- 只读取和修改当前指定文件夹，不要访问其他目录；
- 不要删除或覆盖原文件，先新建一个输出文件夹存放结果；
- 涉及事实、数据或课程要求时，找不到依据的地方直接标注“待核实”，不要自行补充。

### 3. 验收标准：做到什么程度才算对

Agent 很难自己判断“好不好看”“够不够用”，你需要把你的[输出格式](/glossary/output-format/)与判断标准写进要求里。

例如做网页时，说明“不安装额外工具，浏览器直接打开即可显示正常、手机屏幕也能阅读”；做资料汇总时，说明“表格必须包含文件名、所属课程、核心主题三列，并列出每份文件里你没看懂或无法识别的部分”。

### 4. 协作节奏：什么时候先停下来问你

凡是涉及**批量改文件、覆盖已有内容、或者方案有多种做法**的任务，不要让它一口气做到底。

在任务里加一句“**先列出你的方案，等我确认后再动手**”，能把一次“开盲盒”变成两次可控的配合。

---

把上面四点放进刚才整理复习资料的场景里，一份清楚的任务描述可以写成这样：

```text
我想整理当前文件夹里的期末复习资料，但不想冒险丢失原文件。

请按下面要求推进：
1. 第一步先只读检查当前文件夹里的所有文件，不要移动、重命名或删除任何文件。
2. 给我看一份分类方案（按课程拆分），并标出文件名太模糊、需要我确认归属的文件。
3. 等我回复确认后，再新建一个 `整理后` 文件夹，把文件复制进去；原文件保持不动。
4. 完成后另外生成一份 `复习索引.md`，只依据文件里实际写到的内容列出各科目录和待核对项，不要自己编造知识点。

第一步完成后先汇报方案，等我确认再执行。
```

## 复杂任务分两步走，比一次全包更稳

当你发现自己的需求越写越长，可以照着这个两步节奏来推进：

1. **先调研与对齐，不动手**：让 Agent 先读文件、查现状、列计划，把不清楚的地方问出来。这个阶段最容易发现它有没有理解错你的意思。
2. **确认后再执行，小步修改**：方向对头再让它生成或修改文件；结果出来后如果只有局部不满意，就像上一篇修改 `CDU.html` 那样，明确指出**保留什么、只改哪里**，不要动辄推翻重来。

## 常见坑与边界提醒

- **一次塞进太多彼此打架的要求**：一段话里同时写十几条细碎的格式和风格限制，模型反而容易漏掉中间的几条。把“核心目标 + 红线”放在第一轮，视觉细节和排版微调留到第二轮，效果通常更稳定。
- **把没说出口的偏好当成默认共识**：比如“页面简洁一点”“命名规范一点”，每个人标准不同。与其事后嫌它做得不对，不如直接举例说明你想要的格式或风格。
- **任务描述写得再细，也不能替代权限控制和结果检查**：提示词本质上是给模型的文字说明，它依然可能看漏要求、执行出错或产生[AI 幻觉](/glossary/hallucination/)。不要把所有安全都押在“我已经叮嘱过它别乱删”上——具体怎么限制 Agent 的真实操作权限，以及拿到结果后重点核对哪些地方，我们会在下一章[权限与结果检查](/guide/permissions-and-review/)继续讲清楚。

## 想再深入一点：提示词撰写参考教程

如果你想进一步系统学习怎么写[提示词](/glossary/prompt/)（比如怎么用[少样本示例](/glossary/few-shot/)约定格式、怎么用分隔符把指令和参考材料隔开、什么时候适合引导模型做[思维链](/glossary/chain-of-thought/)分步推导），可以参考下面这几份资料。它们写得比网上流传的“万能模板”更扎实，也更贴近当前主流模型的工作方式：

- **[Prompt Engineering Guide（中文版）](https://www.promptingguide.ai/zh)**：开源社区整理的中文提示工程入门指南，从提示词基本要素讲到零样本/少样本提示、思维链等常用方法，适合想用中文系统补一遍基础概念的同学。
- **[OpenAI · Prompt engineering](https://platform.openai.com/docs/guides/prompt-engineering)**（英文）：围绕六条核心策略展开，包括写清指令细节、提供参考资料、把复杂任务拆成子步骤、给模型留出推理步骤等，里面有不少可以直接对照改写的例子。
- **[Anthropic · Prompt engineering overview](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview)**（英文）：重点讲清为什么“直接、明确、少歧义”比玄学套话更有效，并介绍了用标签分隔上下文与指令、提供输入输出示例等实用做法。
- **[Google Gemini · Prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies)**（英文）：从角色、任务目标、上下文和输出约束四个角度梳理提示词结构，适合参考如何把长提示词写得层次分明、方便反复迭代修改。

读这些资料时可以记住一个原则：**技巧是用来把你的真实需求说得更清楚的，而不是让你每次用 Agent 都硬套一整套格式。** 日常任务先交代清楚目标、边界、验收标准和确认节点，已经能解决大部分问题；遇到复杂或需要反复跑的任务，再从这些文档里挑一两条合用的方法来补强就够了。
