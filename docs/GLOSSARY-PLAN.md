## 1. 两层分类

术语页左侧是「分支树」，按 git graph 的方式组织：

```text
[AI] AI 主线
  ├ 基础
  ├ 提示词
  ├ 工具
  ├ Agent
  ├ 安全
  └ 成本
      ╰─→ [vibecoding] Vibe Coding
              ├ 前端 / 后端 / 产品 / 测试 / Git
```

- 分支点在主线的**末端**：主线走完 6 个 AI 分类后，用一条连接线拐到 vibecoding 分支，不并行、不抢占主线空间。
- 两个分支头（`AI` / `vibecoding`）都可以**折叠**，收起后只留分支头与计数。
- **默认停在 `AI 主线`**：打开页面先看到 AI 主分支的内容，延伸分支需要点击分支头才会展开显示，不再有「一屏看到全部」的入口。
- 分支头点击 = 按整个分支筛选（合并该分支下所有分类）；分类节点点击 = 只看该分类。
- 节点颜色跟随所在分支（主分支蓝、vibecoding 紫）；`清除筛选` 回到默认的 AI 主线。
- 延伸分支的 5 个技术类目挂在 Vibe Coding 之下：先通过 vibe coding 接触 AI 做东西，再撞到前端 / 后端 / 产品 / 测试 / Git。

## 2. 术语模块结构（页面区块）

页面已支持一句话释义、校园示例、Markdown 正文，以及可选的「你可能会说」、场景拆解、选择题、Agent 提示词、相关词条与参考来源。字段约束和两类词条写法统一维护在 [内容规范第 5 节](CONTENT-GUIDE.md#5-术语表)，可复制示例在 [术语模板](../src/content/glossary/_TEMPLATE.md)，不在规划中重复列字段表。

## 3. 两类词条的写法不同

AI 主分支帮助理解与使用，延伸分支只帮助读者理解相关术语。AI 主分支使用六段结构；延伸分支使用四段短文，不教操作步骤。来源、篇幅、定义长度与 AI 协助边界见 [现行写作规范](CONTENT-GUIDE.md#5-术语表)。

## 4. 分批节奏

| 批次 | 内容 | 谁做 | 产出 |
| --- | --- | --- | --- |
| 批 0 | **2 条示范**：1 条 AI 主分支 + 1 条延伸分支，走完「起草 → 查证 → 审核确认 → 合并」 | 人起草与确认结论；Agent 可初审、辅助审核与工程校验 | 展示有依据、有负责人的审核记录，现行规则见 [审校规范](CONTENT-REVIEW.md) |
| 批 1 | `basics` 8 条 + `prompt` 8 条 | 同上 | 16 条 |
| 批 2 | `tools` 6 条 + `safety` 6 条 | 同上 | 12 条 |
| 批 3 | `cost` 5 条 + `agents` 7 条 + 延伸分支 18 条（按分支逐个小 PR） | 同上 | 30 条 |

每个 PR 只做一个分支的一批词条，便于逐条审校。

## 5. 分工

- **人**：选题、确定定义与判断、起草正文、按 [`CONTENT-REVIEW.md`](CONTENT-REVIEW.md) 第 5 节逐条核校并签字。
- **Agent**：核对来源链接是否可打开、口径是否与官方文档一致、字段与格式、内链与 `related`、搜索索引、测试与构建；不代写「亲测」，不代签 `reviewed`。
