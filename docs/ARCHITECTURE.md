# M0 架构说明

## 1. 目标与边界

M0 的目标是交付一个**设计完整、结构清晰、可运行、可持续迭代**的静态站点，而不是提前实现论坛。

范围内：

- 品牌与信息架构、全站导航、响应式布局、深浅色主题
- 首页、学习指南（列表 + 详情）、工具目录、作品广场（列表 + 详情）、社区、活动、关于/共建、404
- 内容与代码分离：Markdown 内容集合 + TypeScript 数据模块
- 基础工程保障：类型检查、构建、内容边界测试、内部链接检查、可访问性与无 JS 降级

范围外（明确留到 M1+）：

- 登录、用户资料、发帖、评论、点赞、投稿表单、后台审核
- 数据库与 API、全文检索服务（M0 只做标题/摘要/标签级静态搜索）、活动报名与通知
- 真实学生作品、真实活动排期、学校官方背书

## 2. 技术决策

### 为什么是 Astro

1. **内容型站点**：绝大多数页面是长文与目录，静态生成比 SPA 更合适。
2. **默认静态 HTML，交互渐进增强**：学习指南在弱网、旧设备上也能读；搜索、筛选、主题与菜单由约 7KB 原生 JS 驱动，禁用 JS 时核心内容仍完整。
3. **内容集合**：frontmatter 由 Zod 校验，字段写错会在构建时失败，适合多人协作。
4. **扩展路径清楚**：未来加评论/投稿时，可保留 Astro 前端，接 Server Islands 或独立 API；无需推倒重来。

不选 Next.js / Vue SPA 的原因：M0 没有复杂状态与登录需求，引入框架运行时和更多配置只会增加维护成本。不选纯手写 HTML 的原因：内容一多就会出现重复导航与样式漂移。

### 渲染与部署

- `output: 'static'`，构建产物是纯静态文件。
- 可部署到任意静态托管（校内服务器 + Nginx、Cloudflare Pages、Vercel、Netlify）。
- 不依赖 Node 运行时、数据库或环境变量。
- 站点尚未配置真实域名，因此未生成 canonical / sitemap；部署后补 `site` 与 sitemap 即可。

## 3. 信息架构

```text
/
├── guide/                  学习指南
│   └── [slug]/             单个学习模块（Markdown）
├── tools/                  工具资源（侧栏筛选 + 目录搜索）
├── works/                  作品广场（示例提案，类别筛选）
├── search-index.json       构建时生成的站内搜索索引（全局搜索用）
│   └── [slug]/             示例提案详情
├── community/              社区版块、讨论起点、公约
├── events/                 活动形式与项目路线
├── about/                  项目定位、透明说明、共建方式
└── 404                     兜底页
```

全局导航保持 5 个一级内容入口（学习指南 / 工具资源 / 作品广场 / 社区 / 活动），首页由品牌标识返回。关于与共建放在页脚，符合低频入口惯例。  
顶栏提供全局搜索（Ctrl/Cmd + K）与主题切换；工具页在桌面端使用左侧筛选栏，移动端折叠为横向筛选，与参考站 VibeHub 的目录式浏览方式一致。

### 关键用户路径

1. **零基础第一次来**：首页「我完全没接触过 AI」→ 学习指南 → 单模块 → 下一步模块
2. **带着具体任务来**：首页「我想找个工具马上用」→ 工具目录筛选 → 官方站点
3. **想找灵感**：首页作品预览 → 作品广场筛选 → 示例详情看提示词与拆解
4. **已知关键词**：顶栏全局搜索 → 指南 / 工具 / 作品详情
5. **想参与**：社区/活动 → 关于 · 共建 → M1 参与路径

每个页面最多两步可以回到主路径；详情页提供上一模块/下一模块或返回列表，不制造死路。

## 4. 内容模型

### Markdown 内容集合

| 集合 | 路径 | 用途 | 关键字段 |
| --- | --- | --- | --- |
| `guide` | `src/content/guide/*.md` | 学习模块 | title, summary, stage, order, duration, outcome, forWho, tools, tags |
| `works` | `src/content/works/*.md` | 作品示例/未来投稿 | title, summary, category, format, tools, prompt, effort, status |

frontmatter 由 `src/content.config.ts` 中的 Zod schema 校验；字段不合法时 `astro build` 直接失败。

### 结构化数据

`src/data/*.ts` 承载工具、社区、活动、导航等短内容，由 `src/data/types.ts` 约束。未来接 CMS 或 API 时，页面只改数据获取层，UI 不动。

### 内容与页面解耦的边界

- **同学维护内容不需要改页面代码**：指南、示例写 Markdown；工具与活动改数据数组。
- **页面只负责展示与组合**：不为每个条目写死版式或手工复制导航。
- **类型先行**：M1 接投稿后台时，沿用 `Tool`、`Work` 等结构或做一次显式迁移，避免字段随意漂移。

## 5. 设计系统

- 视觉方向参考 VibeHub 的白底、蓝色交互色与目录式信息密度；不复制其代码、品牌或页面。
- 语义化 CSS 令牌：颜色、字体、间距、圆角、阴影、动效时长集中管理。
- 支持深浅两套主题，读取 `localStorage` 或系统偏好；禁用 JS 时默认浅色且内容完整可读。
- 断点：480 / 760 / 1020 / 1180 / 1280；主要按钮 ≥ 42px，移动菜单 48px。
- 动效只做辅助：搜索框淡入、卡片抬升、筛选过渡；全部受 `prefers-reduced-motion` 控制。
- 无外部字体、无追踪脚本、无 CDN 依赖，离线可完整运行。
- 工具页桌面端为「左筛选栏 + 右卡片网格」，移动端折叠为横向分类。

详见 [`DESIGN-SYSTEM.md`](DESIGN-SYSTEM.md)。

## 6. 可访问性

- 语义化 landmark、跳转链接、唯一 h1、可见焦点环。
- 移动菜单使用原生 `<details>`，无 JS 也可打开。
- 筛选用 `aria-pressed` 与实时结果计数；空结果有明确提示。
- 全局搜索使用原生 `<dialog>`，支持 Ctrl/Cmd + K、↑/↓、Enter、Esc；搜索结果不离开浏览器。
- 颜色对比达到 WCAG AA；状态不只靠颜色表达。
- 浅色与深色主题均用 axe-core 扫描 WCAG A/AA + best-practice，M0 最终结果为零违规。
- 尊重减少动效偏好。

## 7. 迭代扩展点

| M1 需求 | 预留方式 |
| --- | --- |
| 作品投稿 | 扩展 `works` schema（作者、授权、封面、链接），页面增加状态与来源字段；投稿先通过表单收集到后台审核 |
| 评论与点赞 | 详情页预留讨论容器；接服务端 API 或轻量评论服务，不改变内容页 URL |
| 用户与登录 | 导航右侧预留账户位置；先做只读游客体验，再引入认证 |
| 活动报名 | 活动数据增加 `date/place/capacity/signup`，页面按状态渲染「待定/报名中/已结束」 |
| 全文搜索 | M0 已有标题/摘要/标签级静态索引；M1 可扩展正文索引、Pagefind 或服务端搜索，并复用现有搜索弹层 |
| 内容审核 | 为 frontmatter 增加 `reviewedBy/reviewedAt` 与 CI 校验，不把审核逻辑写进页面 |

## 8. 演进路线

### M0（当前）

- 静态框架、内容模型、设计系统、6 个核心内容区
- 全局搜索、工具侧栏筛选、作品类别筛选、深浅色主题
- 只做示例与规划展示，不虚构真实数据
- 构建、类型、内容测试、链接检查与 axe 扫描可运行

### M1：内容与投稿闭环

1. 招募 3–5 名内容维护者，建立选题与事实核对流程
2. 扩充指南与工具，新增 8–12 个跨专业示例
3. 做最简单的投稿：外部表单或邮件 → 人工审核 → 写入 Markdown → 构建发布
4. 社区先在协会内部与邀请制中试运行，不急于全站开放

### M2：社区试运行

1. 引入账号与作品详情页的讨论能力
2. 活动页接入真实排期与报名，明确负责人
3. 增强站内搜索（正文检索、排序与空结果引导）与必要的内容统计（不加入第三方追踪）
4. 根据真实使用反馈重做首页信息优先级，而不是继续加卡片

## 9. 验证与质量

`npm run verify` 是统一入口，包含：

1. `astro check`：Astro/TypeScript 类型与内容 schema 检查。
2. `astro build`：static 生产构建。
3. `node --test tests/site.test.mjs`：检查 20 个页面存在、文档结构、唯一 h1、M0 示例/筹备状态标注、非官方声明、搜索索引覆盖类型与外链安全属性。
4. `scripts/check-links.mjs`：扫描构建后的 HTML，检查站内链接与锚点是否存在。

视觉验收另外在 320 / 390 / 768 / 1024 / 1440px 下用 Playwright 检查；可访问性用 axe-core 在浅色/深色主题以及搜索弹层打开状态下扫描 WCAG A/AA 与 best-practice 规则。M0 最终扫描为零违规；真实浏览器截图与脚本不进入代码仓库（`work/` 已忽略）。

## 10. 已知限制

- 没有真实作品、活动、社区帖子，这是 M0 的刻意选择，不是数据缺失。
- 全局搜索覆盖页面标题、摘要、标签与工具/作品元信息，不做正文全文检索。
- 静态站点的内容更新需要重新构建；M1 可接入自动构建或轻量 CMS。
- 外部工具链接可能随工具官网调整而变化，需要定期维护。
