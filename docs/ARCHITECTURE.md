# M0 架构说明

本文维护整体技术关系、内容模型与阶段边界。主题、工具目录和搜索的内部实现分别见[主题系统](modules/theme.md)、[工具目录](modules/tool-catalog.md)、[站内搜索](modules/search.md)；文档分工见[文档导航](README.md#文档职责)。

## 1. 目标与边界

M0 的目标是交付一个**设计完整、结构清晰、可运行、可持续迭代**的静态站点，而不是提前实现论坛。

范围内：

- 品牌与信息架构、全站导航、响应式布局、深浅色主题
- 首页、学习指南（列表 + 详情）、术语表、工具目录、作品广场（列表 + 详情）、社区（暂不开放）、活动、关于/共建、404
- 章节级站内搜索、内容更新时间 / 参考来源 / GitHub 编辑入口
- 学习指南正文采用 Notion 风格排版，保留目录、阅读路径与页内锚点
- 内容与代码分离：Markdown 内容集合 + TypeScript 数据模块
- 基础工程保障：类型检查、构建、内容边界测试、内部链接检查、可访问性与无 JS 降级

范围外（明确留到 M1+）：

- 登录、用户资料、发帖、评论、点赞、投稿表单、后台审核
- 数据库与 API、服务端全文检索与中文分词、活动报名与通知（M0 使用构建时静态索引）
- 真实学生作品、真实活动排期、学校官方背书

## 2. 技术决策

### 为什么是 Astro

1. **内容型站点**：绝大多数页面是长文与目录，静态生成比 SPA 更合适。
2. **默认静态 HTML，交互渐进增强**：学习指南在弱网、旧设备上也能读；搜索、筛选、主题与菜单由原生脚本增强，禁用 JS 时核心内容仍可阅读。
3. **内容集合**：frontmatter 由 Zod 校验，字段写错会在构建时失败，适合多人协作。
4. **扩展路径清楚**：未来加评论/投稿时，可保留 Astro 前端，接 Server Islands 或独立 API；无需推倒重来。

不选 Next.js / Vue SPA 的原因：M0 没有复杂状态与登录需求，引入框架运行时和更多配置只会增加维护成本。不选纯手写 HTML 的原因：内容一多就会出现重复导航与样式漂移。

### 渲染与部署

- `output: 'static'`，构建产物是纯静态文件。
- 可部署到任意静态托管（校内服务器 + Nginx、Cloudflare Pages、Vercel、Netlify）。
- 不依赖 Node 运行时、数据库或环境变量。
- 公开部署地址通过 `astro.config.mjs` 的 `site` 配置，页面据此生成 canonical；开发预览或正式域名变化时同步更新。当前未引入 sitemap 生成器。

## 3. 信息架构

```text
/
├── guide/                  学习指南
│   └── [slug]/             单个学习模块（Markdown + 更新时间 / 来源 / 编辑入口）
├── glossary/               术语表（分类筛选，条目由内容集合生成）
│   └── [id]/               单个术语的白话详解（类比 / 运作 / 场景 / 误解）
├── tools/                  工具资源（侧栏筛选 + 目录搜索）
├── works/                  作品广场（示例提案，类别筛选）
│   └── [slug]/             示例作品详情
├── search-index.json       构建时生成的章节级站内搜索索引
├── community/              社区（暂不开放，仅保留提示页）
├── events/                 活动形式与项目路线
├── about/                  项目定位、透明说明、共建方式
└── 404                     兜底页
```

顶栏提供学习指南、术语表、工具资源、作品广场、活动及关于与共建入口，首页由品牌标识返回。社区暂不开放，仅保留提示页与页脚入口。学习指南正文采用 Notion 风格排版，不新增独立文档站。
顶栏提供全局搜索（Ctrl/Cmd + K）与主题切换；工具页在桌面端使用左侧筛选栏，移动端折叠为横向筛选，采用目录式浏览。

### 关键用户路径

1. **零基础第一次来**：首页「开始学习」或「先认识 AI」→ 学习指南 → 已有正文；模块补充后可继续阅读单模块
2. **带着具体任务来**：首页「找个工具试试」→ 工具目录筛选 → 官方站点
3. **想找灵感**：首页应用场景展台浏览与换卡；作品广场仍从顶栏进入，当前内容状态以作品页为准
4. **已知关键词**：顶栏全局搜索 → 指南章节 / 术语 / 工具 / 作品详情（带锚点）
5. **想参与**：活动 → 关于 · 共建 → M1 参与路径

每个页面最多两步可以回到主路径；详情页提供上一模块/下一模块或返回列表，不制造死路。

首页应用展台的三组卡片各含五个应用场景，仅用于表达 AI 的应用可能，不提供场景跳转或站内执行任务；卡片文案与概念插画由 `src/data/home-scenarios.ts`、`HomeScenarios.astro`、`ScenarioArt.astro` 和 `ScenarioWorkspaceArt.astro` 维护。操作浏览器和 MATLAB 等专业软件也是概念示意，不表示本站接入了软件控制能力。首页不再展开空的学习阶段、作品占位和社区活动卡片，后续入口与共建邀请集中在轻量探索区。

轻量探索区由 `HomeExploreMenu.astro` 提供指南、工具与术语入口，悬停和键盘聚焦的流动横幅由原生 CSS 与 `home-explore-menu.ts` 增强；触屏、减少动效和无 JS 时仍可直接通过链接导航。横幅示意图由 `ExploreMenuArt.astro` 绘制，重复内容不进入可访问树。

探索区以「开始探索AI」为标题，`ExploreDotField.astro` 在主题表面色面板中呈现抽象点阵，不使用固定黑白背景或外部图片。`lib/explore-dot-field.ts` 为静态 SVG 与 Canvas 共用曲面几何，`scripts/explore-dot-field.ts` 读取主题颜色并管理指针、尺寸与可见性；三个流动入口的内容、链接和交互保持独立。

## 4. 内容模型

### Markdown 内容集合

| 集合 | 路径 | 用途 | 关键字段 |
| --- | --- | --- | --- |
| `guide` | `src/content/guide/*.md` | 学习模块 | title, summary, stage, order, outcome, forWho, updated, sources, tools, tags, reviewed, reviewedBy, needsUpdate, basis, aiUsage, testedOn, testedEnvironment, contributors |
| `works` | `src/content/works/*.md` | 作品示例/未来投稿 | title, summary, category, format, tools, prompt, effort, status, updated, 以及通用审校字段 |
| `glossary` | `src/content/glossary/*.md` | 术语词条 | term, en, category, definition, example, order, related, sources, updated, 以及通用审校字段 |

三个集合共用一组内容状态字段（`reviewed` / `reviewedBy` / `needsUpdate` / `basis` / `aiUsage` / `testedOn` / `testedEnvironment` / `contributors`），页面状态由字段推导：缺少 `reviewed` 或 `reviewedBy` 时显示「初稿 · 尚未审核」，同时填写且未标记待更新才显示「已审核无误」。审核可使用 AI 初审与辅助审核，由审核负责人确认结论；过程记录保存在 GitHub。字段与流程规范见 [`CONTENT-REVIEW.md`](CONTENT-REVIEW.md)。

内容重建始于 2026-10-20。当前已有指南首页、「这份指南适合谁」文章与分类术语词条，其余指南章节与作品逐步补充；术语各批次的审校范围和方式见[文档导航](README.md)，不由条目数量推断审核完成。

各目录保留写作模板。glob 模式为 `**/[!_]*.md`，**以 `_` 开头的文件不作为内容集合条目加载**；`src/content/guide/_HOME.md` 由指南首页直接导入并显示在 `/guide/`，不生成单独的文章路由，不自动追加介绍、目录总览或阶段列表。首页审核规则与记录方式见 [内容审校规范](CONTENT-REVIEW.md#指南首页与独立页面正文)，不增加页面审核信息栏。作品与术语集合为空时仍显示占位，测试与检查器支持空集合。

指南的 `stage` 决定学习阶段，`order` 是指南集合内全局唯一的正整数，用于集合排序；`src/data/guide-nav.ts` 决定六个目录分组与章节阅读顺序。共享 `GuidePager.astro` 按目录连接首页和所有登记的章节，首尾只显示实际存在的方向，资源入口不参与章节翻页。已登记但尚无 Markdown 的章节生成可访问的占位路由，标注正文待补充，不计入正式文章与搜索索引；补上同名 Markdown 后自动显示正文。新增指南需要同时创建 Markdown 并登记 slug，不在新阶段重置 `order`。

frontmatter 由 `src/content.config.ts` 中的 Zod schema 校验；字段不合法时 `astro build` 直接失败。

### 结构化数据

`src/data/*.ts` 承载工具、活动、导航等短内容，由 `src/data/types.ts` 约束。术语的词条正文改为 content collection（`src/content/glossary/*.md`）：frontmatter 存结构、别名和一句话释义，正文写白话详解；分类仍由 `src/data/glossary.ts` 维护，搜索索引与详情页都从同一份内容生成。未来接 CMS 或 API 时，页面只改数据获取层，UI 不动。

### 工具目录的数据模型

工具条目保存在 `src/data/tools.ts`，由 `Tool` 类型约束；场景分类、页内分区、资源形态和技术类型分别表达不同维度。页面从数据生成卡片和视图，浏览器再增强筛选、折叠和手机分页。

字段、收录依据、官网/仓库入口与图标规则统一见[工具数据规范](CONTENT-GUIDE.md#6-工具数据)。分区覆盖、关联栏目、旧分类别名、客户端生命周期和新增分类的影响面见[工具目录开发说明](modules/tool-catalog.md)。

### 内容与页面解耦的边界

- **同学维护内容不需要改页面代码**：指南、示例写 Markdown；工具与活动改数据数组。
- **页面只负责展示与组合**：不为每个条目写死版式或手工复制导航。
- **类型先行**：M1 接投稿后台时，沿用 `Tool`、`Work` 等结构或做一次显式迁移，避免字段随意漂移。

## 5. 设计系统

- 视觉方向：跟随浅色、深色与自定义主题的语义配色、目录式信息密度；不复制任何第三方项目的代码、品牌或页面。
- 语义化 CSS 令牌：颜色、字体、间距、圆角、阴影、动效时长集中管理。
- 支持内置深浅色、预设和本浏览器自定义主题。首屏、参数推导、按需加载、编辑会话及各类存储失败的实际行为见[主题系统开发说明](modules/theme.md)。禁用 JS 时默认浅色且内容完整可读。
- 首页、工具、作品、活动、关于、社区和错误页的专属样式放在 `src/styles/routes/`，由对应页面导入。指南和术语共用的阅读布局整理到 `reading.css`，与目录筛选布局保留在全站共享样式中，维持原有覆盖顺序；指南和术语仍按页加载 `notion.css`、`glossary.css`。全站基础、导航、搜索和共享组件样式由 `global.css` 加载，保持语义令牌与减少动效支持。
- 断点：480 / 760 / 1020 / 1180 / 1280；主要按钮 ≥ 42px，移动菜单 48px。
- 动效只做辅助：搜索框淡入、卡片抬升、筛选过渡；全部受 `prefers-reduced-motion` 控制。
- 站点预设字体和素材自托管，不依赖外部字体服务、追踪脚本或 CDN；自定义主题可由用户填写外部图片或 https 字体地址。外部工具和参考资料依赖各自的网络访问条件。
- 工具页桌面端为「左筛选栏 + 右卡片网格」，移动端折叠为横向分类。

详见 [`DESIGN-SYSTEM.md`](DESIGN-SYSTEM.md)。

## 6. 可访问性

- 语义化 landmark、跳转链接、唯一 h1、可见焦点环。
- 移动菜单使用原生 `<details>`，无 JS 也可打开。
- 筛选用 `aria-pressed` 与实时结果计数；空结果有明确提示。
- 全局搜索由 `scripts/search.ts` 管理，使用原生 `<dialog>`，支持 Ctrl/Cmd + K、↑/↓、Enter、Esc；输入法组词期间不拦截按键。索引按需加载并在成功后复用，失败可以点击重试或重新打开搜索。最多展示前 10 条，同时显示实际匹配总数；搜索结果不离开浏览器。
- 颜色对比达到 WCAG AA；状态不只靠颜色表达。
- 浅色、深色主题及搜索弹层应分别检查 WCAG A/AA 与 best-practice；扫描结果需按实际版本记录。
- 尊重减少动效偏好。

## 7. 迭代扩展点

| M1 需求 | 预留方式 |
| --- | --- |
| 作品投稿 | 扩展 `works` schema（作者、授权、封面、链接），页面增加状态与来源字段；投稿先通过表单收集到后台审核 |
| 评论与点赞 | 详情页预留讨论容器；接服务端 API 或轻量评论服务，不改变内容页 URL |
| 用户与登录 | 导航右侧预留账户位置；先做只读游客体验，再引入认证 |
| 活动报名 | 活动数据增加 `date/place/capacity/signup`，页面按状态渲染「待定/报名中/已结束」 |
| 全文搜索 | M0 已有页面、指南/作品章节与术语的静态索引，并支持锚点跳转；M1 可增加中文分词、相关度排序、Pagefind 或服务端搜索 |
| 内容审核 | M0 已实现 `reviewed/reviewedBy`、状态推导、页面状态展示与审校清单（见 `docs/CONTENT-REVIEW.md`）；M1 增加复核周期提醒、工具目录接入与更细的权限控制 |

## 8. 演进路线

### M0（当前）

- 静态框架、内容模型、设计系统、6 个一级内容区
- 章节级全局搜索、AI 术语表、学习指南 Notion 风格正文、工具侧栏筛选、作品类别筛选、深浅色主题
- 指南 / 作品的更新时间、参考来源与 GitHub 编辑入口
- 只做示例与规划展示，不虚构真实数据
- 构建、类型、内容测试、锚点与链接检查纳入统一验证；视觉和可访问性检查单独执行与记录

### M1：内容与投稿闭环

1. 招募 3–5 名内容维护者，建立选题与事实核对流程
2. 扩充指南与工具，新增 8–12 个跨专业示例
3. 做最简单的投稿：外部表单或邮件 → 人工审核 → 写入 Markdown → 构建发布
4. 社区功能目前关闭；是否在 M1 重启需重新评估，不自动开放

### M2：社区试运行

1. 引入账号与作品详情页的讨论能力
2. 活动页接入真实排期与报名，明确负责人
3. 增强站内搜索（分词、相关度排序与空结果引导）与必要的内容统计（不加入第三方追踪）
4. 根据真实使用反馈重做首页信息优先级，而不是继续加卡片

## 9. 验证与质量

`npm run verify` 依次执行类型检查、内容与文档校验、生产构建、自动测试和站内链接检查。命令、检查范围与排障集中在[维护说明](MAINTAINING.md#验证入口)；各模块说明列出对应测试和关键行为。

内容检查以 schema、引用、日期、排序和审校字段组合为边界，合法/错误样例放在 `tests/fixtures/content/`。页面与索引检查从实际内容生成清单，不把历史条目数作为当前验收依据。文档链接检查只能验证结构，不能证明说明与实现语义一致。

视觉验收覆盖手机、平板和桌面断点；可访问性检查覆盖深浅主题及搜索弹层，结果与工程检查分别记录。用于长期说明的少量截图放在 `docs/screenshots/`，临时 QA 资料放入已忽略的 `work/`。M0 是否完成仍以人工验收记录为准。

## 10. 已知限制

- 社区功能在 M0 关闭，没有真实作品、活动排期与社区帖子；这是刻意选择，不是数据缺失。
- 全局搜索使用构建时静态索引，不做中文分词、相关度学习或跨站搜索；来源、章节门槛、排序和失败重试见[站内搜索开发说明](modules/search.md)。
- 静态站点的内容更新需要重新构建；M1 可接入自动部署或轻量 CMS。
- 外部工具链接可能随工具官网调整而变化，需要定期维护。
